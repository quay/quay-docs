= Enabling read-only mode for {productname-ocp}

[role="_abstract"]
Read-only mode keeps your {productname-ocp} registry online during backup and restore by blocking write operations. You can use this mode when scaling down the deployment is unacceptable.

When backing up and restoring, you are required to scale down your {productname-ocp} deployment. This results in service unavailability during the backup period which, in some cases, might be unacceptable. Enabling read-only mode ensures service availability during the backup and restore procedure for {productname-ocp} deployments.

[NOTE]
====
In some cases, you cannot enable read-only mode for {productname} because it requires inserting a service key and other manual configuration changes. As an alternative to read-only mode, {productname} administrators might consider enabling the `DISABLE_PUSHES` feature. When this field is set to `True`, users are unable to push images or image tags to the registry when using the CLI. Enabling `DISABLE_PUSHES` differs from `read-only` mode because the database is not set as `read-only` when it is enabled.

This field might be useful in some situations such as when {productname} administrators want to calculate their registry's quota and disable image pushing until after calculation has completed. With this method, administrators can avoid putting the whole registry in `read-only` mode, which affects the database, so that most operations can still be done.
====

There are two methods to enable read-only mode for {productname-ocp}:

Operator-managed method:: The Operator-managed method is available in {productname} {producty} and later. It allows the {productname} Operator to manage the read-only lifecycle for {productname-ocp} deployments. This method is the preferred method for enabling read-only mode for {productname-ocp}.

Manual method:: The manual method is the traditional method of enabling read-only mode for {productname-ocp}. It requires you to manually insert a service key and make configuration changes. When the Operator detects `REGISTRY_STATE: readonly` set manually in the configuration, it defers image version upgrades and database migration jobs and sets a `ManualReadOnlyDetected` status condition.

[IMPORTANT]
====
The two methods are mutually exclusive. If `REGISTRY_STATE: readonly` or any `INSTANCE_SERVICE_KEY_*` key is present in your config Secret, the Operator blocks operator-managed read-only mode with a `ManualMigrationRequired` condition. If the conflict is in a `QUAY_OVERRIDE_CONFIG` environment variable override, the condition reason is `OverrideConflict`. Remove the conflicting keys before using the Operator-managed method.
====

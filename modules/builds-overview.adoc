= Container image builds

[role="_abstract"]
{productname} can build container images from Dockerfiles on worker nodes. You can start builds manually or automatically from source-control events so that registry images stay aligned with your code.

Builds are supported on {productname-ocp} and Kubernetes. A build manager coordinates build jobs. You can run builders on bare metal nodes or as virtual (unprivileged container) builders, depending on isolation needs and available infrastructure.

When you plan builds, decide whether {productname} should own image builds in your pipeline or whether an external CI system should push finished images into the registry. If you use {productname} builds, choose a builder strategy and confirm networking constraints for your cluster.

[NOTE]
====
Running builds directly in a container on bare metal does not provide the same isolation as virtual machines, but it still provides meaningful process isolation.
====

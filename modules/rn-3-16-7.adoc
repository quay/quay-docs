[id="bug-fixes-316-7"]
== {productname} 3.16.7 bug fixes

* link:https://issues.redhat.com/browse/PROJQUAY-14044[*PROJQUAY-14044*]. Previously, fetching archived build logs from Google Cloud Storage could return HTTP 500 with a zlib "incorrect header check" error when GCS served an already-decoded object that {productname} still tried to decompress as gzip.
+
With this release, archived build log readers accept both gzip-compressed and already-decoded archive content. As a result, archived build logs on GCS storage load successfully.

* link:https://issues.redhat.com/browse/PROJQUAY-13419[*PROJQUAY-13419*]. Previously, organization administrators could not update the quota limit for their own organization from the v2 UI, because the `changeOrganizationQuota` API returned an unauthorized error.
+
With this release, organization administrators can update organization quota limits from the v2 UI and API. As a result, quota changes no longer fail with an unauthorized error for organization admins.

* link:https://issues.redhat.com/browse/PROJQUAY-13337[*PROJQUAY-13337*]. Previously, when quota enforcement rejected a blob upload, the `BlobUpload` row was left behind and inflated later in-flight size calculations, so subsequent pushes could be permanently rejected.
+
With this release, rejected uploads no longer leave orphaned `BlobUpload` rows that block later pushes. As a result, namespaces recover correctly after a quota reject.

* link:https://issues.redhat.com/browse/PROJQUAY-13322[*PROJQUAY-13322*]. Previously, the Superuser Build Logs page in the new UI could show "No logs available" for archived builds even when archived logs existed.
+
With this release, archived build log retrieval for the Superuser Build Logs page is corrected. As a result, archived builds show their logs when available.

* link:https://issues.redhat.com/browse/PROJQUAY-13319[*PROJQUAY-13319*]. Previously, the Superuser Build Logs page in the new UI could return HTTP 500 because of a logic error in `BuildTrigger.to_dict()`.
+
With this release, that serialization path is corrected. As a result, the Superuser Build Logs page loads without a 500 error.

* link:https://issues.redhat.com/browse/PROJQUAY-11694[*PROJQUAY-11694*]. Previously, lazy load of OCI indexes failed when the index included Docker v2 schema 2 images.
+
With this release, lazy loading tolerates Docker v2 schema 2 images in an OCI index. As a result, those indexes can be loaded successfully.

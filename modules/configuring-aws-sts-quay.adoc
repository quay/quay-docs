= Configuring AWS STS for {productname}

[role="_abstract"]
You can configure AWS Security Token Service (STS) with {productname} to authenticate to Amazon S3 by using temporary credentials. STS is available for standalone deployments, {productname-ocp}, and {productname} on Red Hat OpenShift Service on AWS (ROSA).

AWS STS provides temporary, limited-privilege credentials for AWS Identity and Access Management (IAM) users. When {productname} uses Amazon S3 as object storage, STS protocols can authenticate access so that sensitive data remains properly authenticated and authorized.

Configuring AWS STS for {ocp} or ROSA can be done using two approaches:

* **Manual STS** — Create an AWS IAM user, create an S3 role, and configure your {productname} `config.yaml` file to include the static user credentials. This approach is supported for standalone, {productname-ocp}, and ROSA deployments.
* **CCO-based STS (OCP 4.14+)** — Use the OpenShift Cloud Credential Operator (CCO) to automatically provision short-lived credentials through the `CredentialsRequest` API. This is the recommended approach for {productname-ocp} on STS-enabled clusters and eliminates the need for static IAM user credentials.

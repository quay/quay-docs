== {productname} 3.18.2 bug fixes

* link:https://issues.redhat.com/browse/PROJQUAY-13380[*PROJQUAY-13380*]. Previously, `RadosGWStorage` did not correctly apply a configured `region_name` during startup validation and could use the default `us-east-1` region instead.
+
With this release, `RadosGWStorage` validates and uses the configured `region_name` at startup. As a result, region-scoped S3-compatible backends receive the expected region in authorization requests.

* link:https://issues.redhat.com/browse/PROJQUAY-13517[*PROJQUAY-13517*]. Previously, proxy cache pulls of large blobs could fail with HTTP 500 when asynchronous download left an orphaned database blob record without storage placement, which blocked later pulls of the same blob.
+
With this release, proxy cache handling of large blob downloads no longer leaves orphaned blob records that permanently block pulls. As a result, large layers can be pulled through the proxy cache reliably.

* link:https://issues.redhat.com/browse/PROJQUAY-13532[*PROJQUAY-13532*]. Previously, blob GET requests through the storage proxy (`FEATURE_PROXY_STORAGE`) were gzip-encoded by nginx, which removed `Content-Length` and could double-compress already gzip-compressed layers.
+
With this release, storage proxy blob responses are not gzip-encoded by nginx. As a result, proxied blob GETs retain `Content-Length` and return the stored bytes without extra compression.

= Robot API token configuration fields

[role="_abstract"]
Review configuration fields that control robot API tokens and federated token exchange for the {productname} management API.

[IMPORTANT]
====
Robot API tokens and federated token exchange for the management API are Technology Preview features in {productname} {producty}. Technology Preview features are not supported with Red Hat production service-level agreements (SLAs) and might not be functionally complete. Red Hat does not recommend using Technology Preview features in production environments. These features provide early access to upcoming product features, enabling customers to test functionality and provide feedback during the development process.
====

.Robot API token configuration fields
[cols="3a,1a,2a",options="header"]
|===
|Field | Type |Description

|**FEATURE_ROBOT_API_TOKENS** |Boolean |When set to `True`, robot accounts can hold expiring, scoped `qro_` tokens for the management API, and the token lifecycle endpoints are available
 +
*Default*: `False`

|**FEATURE_ROBOT_API_TOKEN_EXCHANGE** |Boolean |When set to `True`, the `POST /sts/token` endpoint is available, which exchanges an external OIDC token for a management API access token. Requires `FEATURE_ROBOT_API_TOKENS` to be set to `True`
 +
*Default*: `False`

|**API_TOKEN_MAXIMUM_TOKEN_COUNT** |Integer |The maximum number of active robot API tokens that a single robot account can hold. A token is active when it has neither expired nor been revoked. Set to `null` to remove the limit
 +
*Default*: `20`
|===

.Robot API token example YAML
[source,yaml]
----
# ...
FEATURE_ROBOT_API_TOKENS: true
FEATURE_ROBOT_API_TOKEN_EXCHANGE: true
API_TOKEN_MAXIMUM_TOKEN_COUNT: 20
# ...
----

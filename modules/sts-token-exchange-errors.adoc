= Token exchange error codes

[role="_abstract"]
A failed request to the `POST /sts/token` endpoint returns a JSON body of the form `{"error": "<code>"}`.

Use the following table to identify the cause.

.Token exchange error codes
[cols="2a,3a",options="header"]
|===
|Error code |Cause

|`invalid_request`
|The request is malformed or missing a required parameter. Specific causes include sending an empty body, using a Content-Type other than `application/x-www-form-urlencoded`, submitting a request body exceeding 32 KiB, providing a `subject_token` exceeding 24 KiB, or supplying an unsupported `subject_token_type` or `requested_token_type`.

|`invalid_grant`
|The external token was rejected. The `issuer` or `subject` is not bound to the robot account, the signature is not valid, the `aud` claim does not match an audience on the federation entry, the token has expired, or a requested scope is outside the entry's `api_scopes`.

|`invalid_target`
|The `resource` parameter does not name a robot account that exists, or the target robot account is invalid.

|`unsupported_grant_type`
|The `grant_type` value is not `urn:ietf:params:oauth:grant-type:token-exchange`.
|===

An `invalid_grant` response covers several distinct causes and does not say which one applied. When you are diagnosing one, check the following items in order:

. Issuer match: The federation entry's `issuer` equals the token's `iss` claim exactly, including any trailing slash.
. Subject match: The federation entry's `subject` equals the token's `sub` claim exactly.
. Audience match: The token's `aud` claim includes one of the entry's `audiences` values.
. Expiration: The token has not expired.
. API scopes present: The matching federation entry defines `api_scopes`. Registry-only federation entries cannot be used with `POST /sts/token`; use `GET /oauth2/federation/robot/token` instead.
. Requested scopes valid: The requested scopes are a subset of the entry's `api_scopes`.
. Robot access restrictions: The robot account is not blocked by the `ROBOTS_DISALLOW` configuration field (unless explicitly listed in `ROBOTS_WHITELIST`).
. Network reachability: The {productname} pods can reach the OIDC issuer's discovery endpoint.

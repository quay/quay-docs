[id="gunicorn-timeout-configuration-fields"]
== Gunicorn worker timeout configuration fields

The following configuration fields allow you to tune the gunicorn worker timeout for the registry and web processes. Previously, the timeout was hardcoded at 30 seconds, which caused worker termination during legitimate long-running operations such as large image pushes, proxy cache blob downloads, and API queries on large organizations with quota enabled.

[cols="2a,1a,3a",options="header"]
|===
|Field |Type |Description

|`GUNICORN_REGISTRY_TIMEOUT`
|Integer
|Specifies the worker timeout, in seconds, for the `gunicorn-registry` process. The minimum value is `30`. The maximum value is `300`. Defaults to `300`.

|`GUNICORN_WEB_TIMEOUT`
|Integer
|Specifies the worker timeout, in seconds, for the `gunicorn-web` process. The minimum value is `30`. The maximum value is `300`. Defaults to `60`.

|===

[id="robot-api-token-configuration-fields"]
== Robot API token configuration fields

The following configuration fields control robot API tokens and federated token exchange for the management API. Both features are Technology Preview in {productname} {producty} and are disabled by default.

[cols="2a,1a,3a",options="header"]
|===
|Field |Type |Description

|`FEATURE_ROBOT_API_TOKENS`
|Boolean
|When set to `true`, robot accounts can hold expiring, scoped `qro_` tokens for the management API, and the token lifecycle endpoints are available. Defaults to `false`.

|`FEATURE_ROBOT_API_TOKEN_EXCHANGE`
|Boolean
|When set to `true`, the `POST /sts/token` endpoint is available, which exchanges an external OIDC token for a management API access token. Requires `FEATURE_ROBOT_API_TOKENS`. Defaults to `false`.

|`API_TOKEN_MAXIMUM_TOKEN_COUNT`
|Integer
|Specifies the maximum number of active robot API tokens that a single robot account can hold. Set to `null` to remove the limit. Defaults to `20`.

|===

[id="oidc-superuser-sync-configuration-fields-500"]
== OIDC superuser group synchronization configuration fields

The following configuration fields are added to the OIDC login service config block to support superuser group synchronization for OIDC-backed deployments.

[cols="2a,1a,3a",options="header"]
|===
|Field |Type |Description

|`SUPERUSER_GROUP`
|String
|Specifies the unique identifier of the OIDC group whose members are granted superuser privileges at login. Users are dynamically added to or removed from the superuser role on each login based on their current OIDC group membership. The identifier format depends on your OIDC provider; for example, Microsoft Entra ID uses a group object ID (UUID), while Keycloak uses a group name. Users listed in `SUPER_USERS` are never deregistered. This field is optional.

|`GLOBAL_READONLY_SUPERUSER_GROUP`
|String
|Specifies the unique identifier of the OIDC group whose members are granted global read-only superuser privileges at login. Members of this group can view all repositories regardless of visibility. The identifier format depends on your OIDC provider. This field is optional.
|===

[id="gunicorn-timeout-configuration-fields"]
== Gunicorn worker timeout configuration fields

The following configuration fields allow you to tune the gunicorn worker timeout for the registry and web processes. Previously, the timeout was hardcoded at 30 seconds, which caused worker termination during legitimate long-running operations such as large image pushes, proxy cache blob downloads, and API queries on large organizations with quota enabled.

[cols="2a,1a,3a",options="header"]
|===
|Field |Type |Description

|`GUNICORN_REGISTRY_TIMEOUT`
|Integer
|Specifies the worker timeout, in seconds, for the `gunicorn-registry` process. The minimum value is `30`. The maximum value is `300`. Defaults to `300`.

|`GUNICORN_WEB_TIMEOUT`
|Integer
|Specifies the worker timeout, in seconds, for the `gunicorn-web` process. The minimum value is `30`. The maximum value is `300`. Defaults to `60`.
|===

[id="operator-managed-read-only-mode-configuration-fields"]
== Operator-managed read-only mode configuration fields

The following internal configuration field is added to support the Operator-managed read-only lifecycle. This field is set automatically by the {productname} Operator and should not be modified manually.

|===
|`INSTANCE_SERVICE_KEY_IMPORT_FROM_FILES`
|Boolean
|When set to `true`, the instance service key is imported from the Operator-mounted `.kid` and `.pem` files (`INSTANCE_SERVICE_KEY_KID_LOCATION` and `INSTANCE_SERVICE_KEY_LOCATION`) instead of being generated at boot. The Operator sets this field to `true` only when the read-only Secret is mounted. Defaults to `False`. This field is for internal use and is managed by the Operator.

|===

[id="robot-api-token-configuration-fields"]
== Robot API token configuration fields

The following configuration fields control robot API tokens and federated token exchange for the management API. Both features are Technology Preview in {productname} {producty} and are disabled by default.

[cols="2a,1a,3a",options="header"]
|===
|Field |Type |Description

|`FEATURE_ROBOT_API_TOKENS`
|Boolean
|When set to `true`, robot accounts can hold expiring, scoped `qro_` tokens for the management API, and the token lifecycle endpoints are available. Defaults to `false`.

|`FEATURE_ROBOT_API_TOKEN_EXCHANGE`
|Boolean
|When set to `true`, the `POST /sts/token` endpoint is available, which exchanges an external OIDC token for a management API access token. Requires `FEATURE_ROBOT_API_TOKENS`. Defaults to `false`.

|`API_TOKEN_MAXIMUM_TOKEN_COUNT`
|Integer
|Specifies the maximum number of active robot API tokens that a single user or robot account can hold. Set to `null` to remove the limit. Defaults to `20`. Creating a token beyond the token limit can result in a `400` error that states `Token limit reached`.

|===

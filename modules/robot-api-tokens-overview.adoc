= Robot API tokens

[role="_abstract"]
Robot API tokens are expiring, scoped credentials that a robot account uses to call the {productname} management API. They are separate from the static push and pull token that every robot account holds.

A robot account has one static token primarily intended for registry access through Docker v2 endpoints; that token does not expire. A robot API token (`qro_`) is different in four ways:

* Dual usage: While designed for the management API, a `qro_` token and an exchanged federated token can also be used as the password for Dockeror OCI v2 registry authentication.
* Expiration: The robot API token expires after at most `90` days. Defaults is `30` days and capped at `90` days.
* Scopes: The robot API token carries a set of OAuth scopes that limit which management API operations it can perform.
* Multiple active tokens: A robot account can hold several active tokens at once, and each token can be managed and revoked individually.

Robot API tokens are prefixed with `qro_`. You send one as a bearer token on the management API, in the same way as an OAuth access token.

The access that a robot API token grants is the intersection of the token's scopes and the robot account's own permissions. A token with the `repo:read` scope lists only the repositories that the robot account has been granted access to. Adding a scope to a token does not grant the robot any permission that it does not already hold.

[IMPORTANT]
====
Robot API tokens are a Technology Preview feature in {productname} {producty}. Technology Preview features are not supported with Red Hat production service-level agreements (SLAs) and might not be functionally complete. Red Hat does not recommend using Technology Preview features in production environments. These features provide early access to upcoming product features, enabling customers to test functionality and provide feedback during the development process.
====

Robot API tokens require the `FEATURE_ROBOT_API_TOKENS` configuration field. You can limit how many active tokens a robot account holds by using the `API_TOKEN_MAXIMUM_TOKEN_COUNT` configuration field.

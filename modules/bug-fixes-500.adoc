= {productname} bug fixes

[role="_abstract"]
You can review bug fixes included in {productname} {producty}.

The following issues were fixed with {productname} {producty}:

* link:https://issues.redhat.com/browse/PROJQUAY-6016[*PROJQUAY-6016*]. Previously, no error notification was displayed in the UI when an invalid robot account description was entered. With this update, proper validation and error feedback are now shown when the robot account description input is invalid.

* link:https://issues.redhat.com/browse/PROJQUAY-6125[*PROJQUAY-6125*]. Previously, the {productname} UI did not validate tag names when a new tag was created, allowing invalid tag names to be submitted without warning. With this update, tag name input is validated in the UI and users receive feedback when an invalid tag name is entered.

* link:https://issues.redhat.com/browse/PROJQUAY-7098[*PROJQUAY-7098*]. Previously, using an email address when creating a repository notification for the first time caused an unexpected error alert in the UI. With this update, the UI correctly handles email-based notification creation without displaying spurious error messages.

* link:https://issues.redhat.com/browse/PROJQUAY-8202[*PROJQUAY-8202*]. Previously, authorizing OAuth applications through the CLI no longer functioned correctly. With this update, CLI-based OAuth application authorization works as expected.

* link:https://issues.redhat.com/browse/PROJQUAY-8272[*PROJQUAY-8272*]. Previously, nested indexes in the {productname} database could cause query performance issues. With this update, nested indexes are corrected to improve database query performance.

* link:https://issues.redhat.com/browse/PROJQUAY-9038[*PROJQUAY-9038*]. Previously, the notification bell badge in the {productname} UI displayed a maximum count of 5, even when more unread notifications were present. With this update, the badge count correctly reflects the actual number of unread notifications.

* link:https://issues.redhat.com/browse/PROJQUAY-9330[*PROJQUAY-9330*]. Previously, when a tag name was the same as the repository name, the repository name was missing from the breadcrumb navigation in the UI. With this update, the breadcrumb correctly displays the repository name in all cases.

* link:https://issues.redhat.com/browse/PROJQUAY-9692[*PROJQUAY-9692*]. Previously, deleting an organization from the superuser admin panel did not generate an audit event. With this update, organization deletions are properly recorded in the audit log.

* link:https://issues.redhat.com/browse/PROJQUAY-11177[*PROJQUAY-11177*]. Previously, changing an organization quota limit using the v2 UI returned a `quota update error, Unauthorized` error even when the user had the necessary permissions. With this update, quota limit changes via the v2 UI succeed for users with appropriate permissions.

* link:https://issues.redhat.com/browse/PROJQUAY-11202[*PROJQUAY-11202*]. Previously, a routing bug in the v2 UI caused malformed API requests when an organization name contained the word `organization`. With this update, organization names containing `organization` are handled correctly in the UI routing layer.

* link:https://issues.redhat.com/browse/PROJQUAY-11278[*PROJQUAY-11278*]. Previously, when `RadosGWStorage` was configured with a `region_name`, the value was not validated at startup, which could result in silent misconfiguration. With this update, `RadosGWStorage` validates `region_name` at startup and reports configuration errors immediately.

* link:https://issues.redhat.com/browse/PROJQUAY-12113[*PROJQUAY-12113*]. Previously, the {productname} UI did not display the cosign shield icon for images that had been signed with cosign. With this update, the shield icon is correctly displayed for cosign-signed images.

* link:https://issues.redhat.com/browse/PROJQUAY-12190[*PROJQUAY-12190*]. Previously, repository mirroring did not work when both the source and destination registries were the same {productname} instance. With this update, repository mirroring functions correctly when the source and destination registries are the same.

* link:https://issues.redhat.com/browse/PROJQUAY-12223[*PROJQUAY-12223*]. Previously, the referrers cache was not invalidated when a manifest was pushed, causing stale referrers to be returned. With this update, the referrers cache is properly invalidated on manifest push, ensuring accurate referrers lists.

* link:https://issues.redhat.com/browse/PROJQUAY-12269[*PROJQUAY-12269*]. Previously, using the `/search` function in the new UI caused the interface to break. With this update, the search function works correctly in the v2 UI.

* link:https://issues.redhat.com/browse/PROJQUAY-12311[*PROJQUAY-12311*]. Previously, the proxy cache failed for large blobs due to an asynchronous download issue. With this update, the proxy cache correctly handles large blobs by resolving the asynchronous download race condition.

* link:https://issues.redhat.com/browse/PROJQUAY-12443[*PROJQUAY-12443*]. Previously, the `/v1/bootstrap/renew` endpoint for the programmatic OAuth token provisioning feature did not properly sanitize input. With this update, the endpoint correctly sanitizes input to prevent unexpected behavior.

* link:https://issues.redhat.com/browse/PROJQUAY-12447[*PROJQUAY-12447*]. Previously, {productname} returned stale caching results on Operator-based deployments. With this update, caching is correctly invalidated on Operator-based deployments, ensuring fresh results are returned.

* link:https://issues.redhat.com/browse/PROJQUAY-12456[*PROJQUAY-12456*]. Previously, the {productname} new UI help dropdown did not display build version information. With this update, the help dropdown shows current build and version information.

* link:https://issues.redhat.com/browse/PROJQUAY-12538[*PROJQUAY-12538*]. Previously, the `tags/list` cache was not invalidated when a manifest was deleted, causing stale tag listings to be returned. With this update, the `tags/list` cache is properly invalidated on manifest deletion.

* link:https://issues.redhat.com/browse/PROJQUAY-12557[*PROJQUAY-12557*]. Previously, orphaned multipart uploads were not cleaned up during blob cleanup, leading to storage accumulation over time. With this update, orphaned multipart uploads are removed as part of the blob cleanup process.

* link:https://issues.redhat.com/browse/PROJQUAY-12773[*PROJQUAY-12773*]. Previously, {productname} generated excessive DNS query bursts that could saturate local DNS resolvers. With this update, DNS query behavior is optimized to prevent resolver saturation.

* link:https://issues.redhat.com/browse/PROJQUAY-12833[*PROJQUAY-12833*]. Previously, the repository mirroring Server-Side Request Forgery (SSRF) mitigation required pod-local DNS resolution, which broke mirroring in disconnected environments that route traffic through an `HTTPS_PROXY`. With this update, repository mirroring works correctly in disconnected environments that use an `HTTPS_PROXY`.

* link:https://issues.redhat.com/browse/PROJQUAY-13363[*PROJQUAY-13363*]. Previously, {productname} ran expensive quota checks even when quota was not configured or required, adding unnecessary overhead to registry operations. With this update, quota checks are skipped when not needed, improving overall registry performance.

* link:https://issues.redhat.com/browse/PROJQUAY-13364[*PROJQUAY-13364*]. Previously, the expiry time for blob and temporary tags was too short, causing premature cleanup of objects still in use. With this update, the blob and temporary tag expiry time is increased to prevent premature deletion.

* link:https://issues.redhat.com/browse/PROJQUAY-13371[*PROJQUAY-13371*]. Previously, registry blob commits blocked for 25–60 seconds due to a double blocking lock acquisition in `with_blob_lock_or_fallback`, causing significant latency during concurrent push operations. With this update, the locking behavior is corrected to eliminate the contention and reduce blob commit latency.

* link:https://issues.redhat.com/browse/PROJQUAY-13405[*PROJQUAY-13405*]. Previously, retrieving archived build logs stored in Google Cloud Storage (GCS) returned a 500 error due to a `zlib` incorrect header check error when GCS served an already-decoded object. With this update, archived build logs are retrieved correctly from GCS storage.

* link:https://issues.redhat.com/browse/PROJQUAY-13429[*PROJQUAY-13429*]. Previously, authentication timeouts occurred with the OIDC backend in large environments due to inefficient token validation. With this update, OIDC authentication is optimized to prevent timeouts in large-scale deployments.

* link:https://issues.redhat.com/browse/PROJQUAY-13519[*PROJQUAY-13519*]. Previously, blob `GET` requests through the storage proxy (`FEATURE_PROXY_STORAGE`) were gzip-encoded by nginx, which removed the `Content-Length` header and caused client compatibility issues. With this update, blob responses through the storage proxy are returned with the correct encoding and `Content-Length` header.

* link:https://issues.redhat.com/browse/PROJQUAY-13543[*PROJQUAY-13543*]. Previously, {productname} application and mirror pods did not roll out when the AWS STS `ROLEARN` was changed in the configuration. With this update, changing `ROLEARN` in the AWS STS configuration triggers the expected pod rollout.

* link:https://issues.redhat.com/browse/PROJQUAY-13715[*PROJQUAY-13715*]. Previously, the {productname} 5.0 Operator displayed the upstream community project logo instead of the Red Hat downstream logo. With this update, the Operator correctly displays the Red Hat {productname} branding.

* link:https://issues.redhat.com/browse/PROJQUAY-13716[*PROJQUAY-13716*]. Previously, the header search box in the {productname} 5.0 UI overlapped the {productname} logo. With this update, the header layout is corrected so the search box and logo do not overlap.

* link:https://issues.redhat.com/browse/PROJQUAY-13780[*PROJQUAY-13780*]. Previously, the {productname} 5.0 Change Log page displayed v3.11.0 release notes instead of v5.0.0 release notes. With this update, the Change Log page correctly displays the v5.0.0 release notes.

Previously, the `last_accessed` field for robot accounts showed `Never` even when the robot account was actively used via API tokens. With this update, global readonly superusers can access robot API token `GET` endpoints as expected.

* link:https://issues.redhat.com/browse/PROJQUAY-13787[*PROJQUAY-13787*]. Previously, the Robot API Tokens tab in the {productname} 5.0 UI displayed tokens as a flat text list instead of a structured table layout.
